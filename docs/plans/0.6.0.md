# Anda 0.6.0 — plan

_2026-10-25 · from 0.5.0 (`6476c88`) · sources: [improvements.md](../../inspiration/improvements.md), [research 003](../research/003-kvaesitso-next-update.md)_

**Theme: "find and keep anything".** Search gets the last big offline sources and actions, and any
result can be pinned. Everything stays offline, and no permission is added.

Per-feature sketches (behaviour, implementation, tests, perf) are in research 003, § *Proposed
next version*. This plan adds the order, the dependencies, one refactor up front, and what runs
in parallel to set up 0.7.0 and 0.8.0.

## Scope

| # | ID | Feature | Effort | Settings key (default) |
|---|---|---|---|---|
| 0 | A4 | Split `SettingsScreens.kt` into one file per screen (no visible change) | S | — |
| 1 | B27 | Script-insensitive search | S | `search.transliterate` (`true`) |
| 2 | B25 | Call and Message on contact results | S | `search.contactActions` (`true`) |
| 3 | B23 | Calendar event search + Events chip | S–M | `search.calendar` (`false`) |
| 4 | B24 | Quick-action editor, app search, custom intents | S–M | `search.quickActionOrder`, `search.disabledQuickActions`, `search.customActions` |
| 5 | B22 | Favorites (pin any result; row in the drawer) | M | `drawer.showFavorites` (`true`) |

About 8–10 working days. Every item gets a feature intake card before it is built
(`docs/research/feature-template.md`).

**Not in 0.6.0:** tags (B8), visibility levels (B7), shortcut exclusions (B26) — they build on the
`ItemKey` that favorites introduces, so they come after it. A3 (`Backupable`) waits for tags too:
favorites is added to `BackupManager` directly for now.

## Order and why

```
A4 split ─┐
          ├─ B27 transliterate ── B25 contact actions ── B23 calendar ── B24 quick actions ── B22 favorites
          │                                            (adds Event)                        (pins App/Shortcut/
          │                                                                                  Contact/Event/Setting)
```

0. **A4 first.** `SettingsScreens.kt` is 1,099 lines and holds every screen but Search, Theme and
   Icons. Move each private screen (`HomeSettingsScreen`, `DrawerSettingsScreen`, … `AboutScreen`)
   into `screens/*.kt`, and `SettingsComponents.kt` into `components/controls` and
   `components/layout`. Favorites adds a row to the Drawer screen; it should land in its own file.
   Pure move, one commit, `SettingsIndexTest` must stay green.
1. **B27** is self-contained and starts with a measurement (load-time target < 15 ms for 300 labels).
   It also precomputes the normalised `originalLabel`, which `AppSearchProvider.kt:22` redoes per
   query today. If the measurement misses, ship only the precompute and move transliteration to 0.6.1.
2. **B25** touches only `ContactSearchProvider` and the contact row. `SearchResult.Contact` gains
   `phone`, which favorites later stores in its payload.
3. **B23** adds `SearchResult.Event` and `SearchCategory.Events`. It goes before favorites so that
   events are pinnable from day one.
4. **B24** is settings plus `QueryActionProvider`. It is independent of favorites, but doing it
   before means the Search settings screen is finished in one pass.
5. **B22 last**, because it is the riskiest: the first Room migration (version 1 → 2), a new
   repository, backups, and a new drawer row on the perf-critical drawer path. `ItemKey(domain, id)`
   covers app, shortcut, contact, event and setting — all five result types exist by then.

## Step 1 measurement (2026-10-25, Pixel 10, debug test APK)

`LatinKeys` (`core/apps`) uses `Transliterator "Any-Latin; Latin-ASCII"` only for labels with
non-Latin letters. `LatinKeysTest` in `core/apps/src/androidTest` produced these numbers:

| Case | Time |
|---|---|
| This phone's 109 real launcher labels (all Latin, ICU never loaded) | 1.1 ms |
| Create the transliterator, fresh process | 58–1,430 ms (most runs 70–200 ms) |
| First key in a script, fresh process | Hangul 20, Devanagari 53, Cyrillic 68–690, Han 520–530, kana 54–190, Thai 210, Arabic / Hebrew / Greek ≈ 1,300 ms |
| Next key in an already-loaded script | 0.2–2 ms |
| 300 labels, 60 of them non-Latin in 17 scripts, cold | 479 ms |

**Result: misses the < 15 ms budget** for any phone with non-Latin labels. The cost is loading ICU
rules, once per script per process; keys are cheap after that. Latin-only phones pay nothing.

**Decision (2026-10-27): ship it with a background build.** `LatinKeyIndex` keys app labels (and
shortcut labels on request) on `Dispatchers.Default`, 3 s after start-up, once per label, and only
while `search.transliterate` is on. Search reads whatever keys exist, so neither cold start nor a
query waits for ICU; a search in the first seconds simply has no Latin matches yet. Typing a query
in another script to find a Latin name (the reverse direction) is not part of this step.

## Rules for this release

- Branch `feat/0.6.0-search-favorites` from the current tip. One conventional commit per numbered
  step (RND.md §3); nothing is pushed without asking.
- `CHANGELOG.md` gets the `0.6.0` heading on the first user-visible step (B27), and one bullet per
  step after that.
- New providers are `slow = true` on `Dispatchers.IO`; app results keep their < 8 ms budget.
- Custom intents: `startActivity` only, at most 10, validated in `SettingsSafety`.
- Favorites: the row is built before the drawer opens, as an immutable list; contact photos decode
  off the main thread at thumbnail size.

## Run in parallel: two spikes for later releases

These need the Pixel 10 and no code from 0.6.0. Each is a ≤ ½-day spike (RND.md §1.3) that ends in
a research note with question, findings, decision and fallback.

|---|---|---|

| B3 Private Space | Is `ACCESS_HIDDEN_PROFILES` granted to a normal app, and does `requestQuietModeEnabled` work while Anda is the default home? | `docs/research/005-private-space.md`; updates research 001 |

(`002` stays reserved for the release baseline.)

## Verification (release gate for 0.6.0)

- `gradlew check` green, including the new tests listed in research 003 for each feature, plus:
  - Room migration test 1 → 2 against `core/data/schemas/2.json`.
  - Backup round-trip with favorites; a 0.5.0 backup still restores.
  - `SettingsSerializationTest`: a 0.5.0 settings file decodes with the new keys at their defaults.
- Instrumented: a pinned contact shows in the drawer row; transliteration on real ICU (Cyrillic, Japanese).
- Macrobenchmark on the Pixel, because the drawer changed: drawer open p95 ≤ 8.3 ms, cold start ≤ 350 ms.
- A UX round on the emulator (`anda-ux-round`) over search, quick actions and favorites.
- Upgrade test: install 0.5.0, add a layout, install 0.6.0 over it — layout, settings and icon
  exceptions survive.

## Changelog draft

```
## 0.6.0 — YYYY-MM-DD
- New: search finds apps by their name in other scripts, so "telegram" finds Телеграм.
- New: Call and Message buttons on contact results.
- New: calendar events in search (Settings → Search → Calendar), with an Events filter chip.
- New: Settings → Search → Quick actions: turn each action on or off, reorder them, open an app's own search with your query, or add your own action.
- New: Favorites. Long-press any search result → Pin to favorites. Pinned items show in a row at the top of the drawer, and can be reordered or removed.
```
