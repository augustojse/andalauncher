# Anda 0.7.0 — plan

_2026-11-03 · from 0.6.0 (`53c5d7e`) · sources: [improvements.md](../../inspiration/improvements.md) (B26), [research 006](../research/006-shortcut-exclusions.md)_

**Theme: "quieter shortcut results".** Search shows the shortcuts of every app, and a few apps flood the list with entries nobody
wants. Users can now switch an app's shortcuts off from the result itself. Everything stays offline, and no permission is added.

Behaviour, implementation, tests and performance are in research 006. This plan adds the order, the version and the gate.
It is deliberately one item: B26 was held back from 0.6.0 because it needed the favorites groundwork, which has now landed.

## Scope

| # | ID | Feature | Effort | Settings key (default) |
|---|---|---|---|---|
| 1 | B26 | Hide shortcuts from an app: long-press menu on a shortcut result, plus Settings → Search → Hidden shortcut apps | S | `search.excludedShortcutApps` (`[]`) |

About 1 working day. The feature intake card is in research 006.

**Not in 0.7.0:** picking apps from a list inside Settings (the first version adds apps from search results only), exclusions for
other result types (B7 visibility levels cover those), and tags (B8).

## Order and why

```
B26 (one step: setting + provider filter + settings screen + long-press item)
```

1. **B26.** The setting and the filter come first inside the step, because the long-press item and the settings screen both read
   the same list. There is no performance risk to measure first: the filter is one set lookup per shortcut, applied to a list that
   already holds at most a few hundred entries. No Room migration, no backup code (settings are already in backups).

## Rules for this release

- Branch `feat/0.7.0-shortcut-exclusions` from the current tip (`6bc64fe`). One conventional commit for the step (RND.md §3); nothing
  is pushed without asking.
- `CHANGELOG.md` gets the `0.7.0` heading with the step. Version: a new feature bumps Y.
- The filter runs at query time, not at cache time, so the shortcut cache stays valid and a change shows on the next keystroke.
- The list is capped (200 packages) and validated in `SettingsSafety`, like `customActions`.
- Clean-room: the behaviour comes from Kvaesitso's 1.41.0 release notes only; no Kvaesitso code was read.

## Verification (release gate for 0.7.0)

- `gradlew check` green, including the new tests listed in research 006, plus:
  - `SettingsSerializationTest`: a 0.6.0 settings file decodes with `excludedShortcutApps` empty.
  - `SettingsIndexTest`: the new Settings row is indexed under its exact title.
- No Room change, so no migration test. No drawer, home or startup change, so no macrobenchmark.
- Instrumented (emulator): long-press a shortcut result → "Hide shortcuts from <app>" → that app's shortcuts disappear → Settings → Search →
  Hidden shortcut apps lists the app → "Show again" brings them back.
- Upgrade check: a settings file written by 0.6.0 loads in 0.7.0 with every setting unchanged (covered by the serialization test).
